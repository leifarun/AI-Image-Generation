- **项目**：豆包 AI 亚马逊卖点图生成工具（内部系统）
- **依据**：PRD v1.0（已确认）
- **状态**：待老板确认

## 第一部分：数据库设计（5 张表 + 2 个文件仓库）

### 表 1：员工表（profiles）—— 记录谁在用系统
| 字段 | 说明 |
|---|---|
| 编号 | 系统自动分配，全局唯一 |
| 姓名 | 界面上显示的名字 |
| 角色 | 管理员 / 运营 |
| 账号状态 | 正常 / 已停用 |
| 创建时间 | |

**权限**：每人可看自己的信息；管理员可看全部、可增改。密码不存这张表，由 Supabase 官方认证系统加密托管。

### 表 2：指令模板表（sop_templates）—— AI 指令的"配方库"
| 字段 | 说明 |
|---|---|
| 编号 | |
| 模板名称 | 如"主图加卖点-标准版" |
| 指令内容 | 可插入占位符：{{竞品标题}}、{{竞品五点描述}}、{{竞品卖点补充}}、{{竞品资料}} |
| 是否默认 | 新建任务时默认选中 |
| 是否启用 | 停用的模板运营看不到 |
| 创建人 / 创建时间 / 更新时间 | |

**权限**：全员可读（运营新建任务时下拉选用）；**仅管理员**可新增、修改。

### 表 3：任务表（tasks）★ 核心台账，一条记录 = 一次生成任务
| 字段 | 说明 |
|---|---|
| 任务编号 | |
| ASIN | 亚马逊商品编号 |
| 站点 | 如 US / UK / DE / JP / CA |
| 卖点说明 | 运营填写 |
| 所用模板编号 | 关联表 2 |
| 组装后指令 | 系统组装好的完整 AI 指令（存档，便于追溯效果） |
| 抓取方式 | 自动 / 手动 |
| 商品标题、五点、商品图 | 抓取到或手动补充的资料 |
| 状态 | 见下方"任务状态一览" |
| 失败原因 | 方便排查 |
| 重试次数 | |
| 提交人 / 提交时间 / 完成时间 | |

**权限**：
- 全员可看全部任务、可提交新任务；
- 提交人可在非处理中状态编辑竞品资料，其余改不动；
- **状态变更只允许云端程序操作**（防止有人绕过排队直接刷接口）；
- 删除：运营只能删自己的任务，管理员可删任意。

### 表 4：结果表（task_results）—— 生成的图片记录
| 字段 | 说明 |
|---|---|
| 编号 | |
| 所属任务编号 | 关联表 3（一个任务将来可对应多张图） |
| 图片路径 | 存在云端文件仓库中的位置 |
| 所用模型 | 豆包模型版本（备将来升级对比） |
| 生成时间 | |

**权限**：全员可看；**仅云端程序可写**。

### 表 5：系统设置表（system_settings）—— 管理员调节的"旋钮"
| 设置项 | 默认值 |
|---|---|
| 同时生成任务数上限 | 2 个 |
| 每分钟最多发起豆包请求数 | 可配置 |
| 默认豆包模型 | 可配置 |
| 站点清单 | US、UK、DE、JP、CA 等 |

**权限**：仅管理员可看、可改。

### 文件仓库 A：产品参考图仓
手动填写竞品资料时，运营上传的商品图存放在这里。规则：登录用户可查看，每人只能上传到自己任务的目录。

### 文件仓库 B：生成结果图仓
豆包生成的图片存放在这里。规则：登录用户可查看；**仅云端程序可写入**；删除跟随任务删除。

### 任务状态一览（状态机）
```
待抓取 → 抓取中 → 排队中 → 生成中 → 已完成
              ↘ 抓取失败 → 失败（记录失败原因，可编辑资料后重试）
                       生成失败 → 失败（自动重试1次，仍失败则标注原因）
```

### 排队与限流的运作方式（像银行叫号）
1. 先提交先处理，公平排队；
2. 同一时间最多 2 个任务"生成中"（超过的在排队池等待）；
3. 每分钟最多发起 N 次豆包请求，防止触发限流；
4. 云端程序每分钟巡检一次队列；有新任务提交时立即唤醒，不等满一分钟。

## 第二部分：界面设计（对标领星 ERP 紧凑企业风）

### 整体布局
- **左侧**：菜单栏（深色收起栏 + 菜单，按角色显示不同菜单）
- **顶部**：面包屑（当前位置）+ 用户名头像 + 退出
- **内容区**：筛选条件 + 数据表格 + 分页；弹窗、抽屉做表单

### 页面清单（8 个页面）
| # | 页面 | 使用者 | 内容 |
|---|---|---|---|
| 1 | 登录页 | 所有人 | 邮箱+密码登录，无注册入口 |
| 2 | 工作台 | 所有人 | 全员任务统计卡（累计任务/排队中/处理中/累计完成/累计失败/累计出图/累计成本）+ 状态下钻任务明细 |
| 3 | 生成任务列表 | 所有人 | 筛选：ASIN、状态、时间、提交人；表格列：时间、提交人、ASIN、站点、卖点摘要、模板、状态、操作 |
| 4 | 新建任务（抽屉） | 运营 | 表单：ASIN、站点下拉、卖点说明多行、模板下拉 |
| 5 | 任务详情 | 所有人 | 资料区、组装后指令、结果大图、状态时间线、失败原因；失败后可编辑资料并重新生成 |
| 6 | 指令模板管理 | 管理员 | 模板表格 + 新建/编辑弹窗 + 启停开关 |
| 7 | 员工账号管理 | 管理员 | 员工表格 + 新增账号弹窗 + 停用开关 + 重置密码 |
| 8 | 系统设置 | 管理员 | 并发数、限流参数、站点清单 |

### 菜单结构
```
工作台        （全员）
生成任务      （全员）
指令模板      （仅管理员）
系统管理      （仅管理员）
 ├─ 员工账号
 └─ 系统设置
```
> 权限不只靠隐藏菜单：数据库层面同样校验，运营直接输网址也进不了管理页。

## 第三部分：安全设计汇总

| 数据 | 谁能读 | 谁能写 |
|---|---|---|
| 员工表 | 本人+管理员 | 管理员 |
| 指令模板 | 全员 | 管理员 |
| 任务表 | 全员 | 提交人（限补资料）、状态仅云端程序 |
| 结果表 | 全员 | 仅云端程序 |
| 系统设置 | 管理员 | 管理员 |
| 文件仓库 A/B | 登录用户 | A：任务提交人上传；B：仅云端程序 |
| 豆包 API 密钥 | **任何人不可见**，存于云端密钥保管箱（Edge Function Secrets） |

## 第四部分：与总控指令的对应关系

- 所有表开启 **RLS 行级安全**（数据库层面的保险锁，逐表已写明策略）；
- 数据库每次结构变更走**版本化迁移**记录，可追溯、可回滚；
- 前端代码使用的数据库类型由 Supabase 官方工具**自动生成**，不手写；
- 时间统一存 **UTC**，界面显示北京时间；
- 业务列表统一使用 **ProTable** 组件（服务端分页、筛选、固定列、空态、加载态）；
- 前端只持有 Supabase 公开键（Publishable Key），豆包密钥**只在服务端**。
