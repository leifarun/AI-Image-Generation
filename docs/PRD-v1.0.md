# 产品需求文档（PRD）v1.0

- **项目名称**：豆包 AI 亚马逊卖点图生成工具（内部系统，暂定名，可随时改）
- **文档日期**：2026-11-19
- **文档状态**：待老板确认
- **面向读者**：项目所有人（无技术背景，全文使用通俗语言）

## 1. 一句话说明

给你们公司**内部使用**的在线工具：运营输入亚马逊商品编号（ASIN）和想加的卖点，系统自动抓取商品资料，调用豆包 AI 生成带卖点的营销图片，排队出图、自动归档。

## 2. 背景

目前运营做卖点图需要：手动复制商品资料 → 手动写 AI 指令 → 逐个生成 → 手动保存。效率低、指令水平因人而异、历史无法追溯。本系统把这套流程**标准化、自动化、可复用**。

## 3. 用户与角色

| 角色 | 能做什么 |
|---|---|
| 老板/管理员 | 管员工账号、创建和维护 SOP 指令模板、配置系统参数、看全部任务 |
| 运营 | 新建生成任务、查看/下载生成结果 |

- 内部工具，**不开放自行注册**，账号由管理员创建。
- 每个运营都能看到全部历史结果（方便复用）。⚠️ 待确认项，见第 9 节。

## 4. 核心流程（一次生成的完整链路）

1. 运营新建任务：填 **ASIN + 国家站点 + 卖点说明 + 选 SOP 模板**
2. 系统自动抓取该商品在对应站点的 **标题、五点描述、产品图**
3. 抓取失败时，任务状态变为"待补充"，页面引导运营**手动粘贴资料**（兜底）
4. 资料齐了 → 组装成 AI 指令 → 进入**排队池**
5. 排队系统按节奏调用**豆包图片生成 API**（避免请求过快被限流）
6. 生成完成 → 图片自动保存归档 → 运营查看/下载
7. 失败的任务标注原因，可一键重新生成

## 5. 功能明细

### 5.1 账号与登录
- 管理员创建账号（邮箱 + 初始密码），员工首次登录改密码
- 登录、退出、修改密码
- 禁止自行注册，未登录无法看到任何内容

### 5.2 SOP 指令模板（管理员专属）
- 模板字段：名称、指令内容（可插入占位符：{{标题}}、{{五点}}、{{卖点}}、{{商品资料}}）、是否默认、启用/停用
- 运营新建任务时从启用模板中下拉选择

### 5.3 新建生成任务（运营）
- 输入：ASIN、站点（下拉选择）、卖点说明（多行文字）、SOP 模板
- 提交后自动开始抓取

### 5.4 资料抓取（自动优先 + 手动兜底）
- 自动：按 ASIN+站点抓取标题、五点、主图
- 兜底：抓不到时任务转"待补充"，运营手动粘贴标题五点、上传图片
- ⚠️ 如实说明：亚马逊有反爬机制，自动抓取无法保证 100% 成功，兜底机制保证功能不中断

### 5.5 排队与限流
- 全局同时生成任务数限制（默认 2 个，管理员可改）
- 每分钟请求上限，防止触发豆包限流
- 任务状态：待抓取 → 抓取中 → 待补充 / 排队中 → 生成中 → 已完成 / 失败
- 失败自动重试 1 次，仍失败则标注原因

### 5.6 豆包 API 调用（服务端加密）
- 豆包密钥**只存放在云端服务端**，前端网页代码里绝不出现
- 由云端程序（Supabase Edge Functions）代理调用豆包生成图片

### 5.7 结果管理
- 历史列表：时间、提交人、ASIN、站点、模板、状态
- 详情页：抓取到的资料、所用指令、结果图片
- 操作：下载、重新生成、删除
- 图片保存在云端存储桶，按公司内部权限访问

### 5.8 用量统计（第二期，第一版不做）
- 每人生成量、成功率、按天统计图表

## 6. 非功能要求

- **安全**：所有数据表开启行级安全（RLS）；密钥只在服务端；禁止公开注册
- **时区**：数据库存 UTC 时间，界面显示北京时间（可配）
- **界面**：参考领星 ERP 的紧凑企业后台风格（仅参考视觉，不复制其素材）
- **部署**：GitHub Pages（网页）+ Supabase（数据库/存储/云端程序）

## 7. 技术底座（总控指令锁定）

Vue 3 + TypeScript + Element Plus + vxe-table + Pinia + Supabase（数据库、登录、存储、Edge Functions）+ ECharts + GitHub Pages / Actions。

## 8. 第一版范围

**包含**：5.1–5.7 全部功能
**不包含（第二期再议）**：批量任务（一次贴多个 ASIN）、用量统计图表、模板版本对比
